## PD

#### `static Game Game { get; }`

The running game, once `SystemEvent.Init` has been handled.

#### `static void Run(Func<Game> factory)`

Registers the game. Call from a `[ModuleInitializer]` method:

```csharp
[ModuleInitializer] internal static void Main() => PD.Run(() => new MyGame());
```

The factory runs when the Playdate sends `SystemEvent.Init`.

- `factory`: Creates the game. Called once, when the system sends `SystemEvent.Init`; must not return null.

#### `static void RunEventHandler(Func<SystemEvent, uint, int> handler)`

Registers a raw event handler, equivalent to the C `eventHandler` function, for games that do not use the `Game` class.

- `handler`: Receives every system event and its argument (the key code for `SystemEvent.KeyPressed`/`SystemEvent.KeyReleased`, otherwise 0) and returns 0.

## Game

```csharp
abstract class Game
```

A Playdate game. Derive from it, register it with `PD.Run` and override `Update`.

The order of calls: the factory passed to `PD.Run` creates the game, `Initialize` runs once, then `Update` runs every frame (30 times a second by default, see `Display.RefreshRate`). Pause, resume, lock and terminate arrive in `OnEvent`. Games with a Lua main loop override `UsesUpdateCallback` and `InitializeLua`.

#### `virtual bool Update()`

Called every frame. Return true to tell the system to update the display (equivalent to returning non-zero from a C update callback).
